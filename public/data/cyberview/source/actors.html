How these profiles are built

Each profile is put together by a script from events CyberView has already checked. Nothing here is written by an AI model, and no group is described beyond what the events say.

  • Attributed: a government or the investigating firm said the group did it. Every row says who said so and links to where.
  • Named in reporting: the reporting an event cites names the group. These are the sources' words, not an attribution by CyberView.
  • Claimed, not confirmed: the group listed the organisation on its leak site. Attackers' claims are often false or exaggerated; they are never counted in the sectors, countries or CVEs.

Other names are joined only on a stated basis: MITRE ATT&CK lists them as aliases, or an event's own sources name them as one group. Each one says which. A name ATT&CK lists under two groups is not matched, and a name seen only in leak-site claims is never matched to an ATT&CK group, because leak-site brands can share a name with an unrelated group.

Computed by a script from CyberView's checked events, not written. Profiles cover only what is on file since CyberView began collecting, so a long-running group may show only its latest activity here.
